HollyHock3, the successor of [Hollyhock2](/wiki/getting-started/introduction/), operates as a custom mod for ClassPad calculators. To make HHK work, you need to **install it on your calculator**. If you have not done this yet, go to our **[Install HollyHock3 MOD](/wiki/hh3/getting-started/install/)** page to learn how to do it.

If you just want to run apps, go to the [ClassPadDev store](https://classpaddev.github.io/store/). If you want to create simple programs and games, start with [Python](/wiki/python/introduction/) and try the [rectangle example](/wiki/python/examples/rectangle/). If you want to create a very fast game, consider [gint](/wiki/gint/getting-started/introduction/). The HH3 SDK is for developers who want to run apps inside the ClassPad OS and want good C++ tooling.

This section of the wiki is about the HH3 SDK, the successor of the HH2 SDK. It keeps similar libraries and the same ease of portability, so most of your old knowledge still applies. It is a good choice when you want to play nicely with the Casio OS, use newer C++ features, and try experimental features. It is also the easiest way to start, because most of the wiki docs are written for it. It is not always the best choice: if you want the best performance for games, the [gint kernel](/wiki/gint/getting-started/introduction/) talks to the hardware directly and is usually faster.

:::tip[ClassPadDev community]
HollyHock3 is a community project, meaning **everyone** plays a part in **making it better**. If you have **questions** or want to be part of the project, **[join our Discord community](https://discord.gg/knpcNJTzpd)**.
:::

## Advanced Development Setup

Most people should start with one of the templates above. But if you want your own development environment, or you want to set up CI/CD, the reference setup is the devcontainer of the HHK3 template. Its [Dockerfile](https://github.com/QBos07/HHK3template/blob/main/.devcontainer/Dockerfile) uses `ghcr.io/classpaddev/hollyhock-3:v2.2.2` as the toolchain stage, then copies `/toolchain` (the compiler) and `/sdk` (the prebuilt SDK) into a Debian 13 base. On top of that it adds make, git, mold, clangd-19 and bear.

```dockerfile
FROM ghcr.io/classpaddev/hollyhock-3:v2.2.2 AS toolchain
```

### Windows

Install [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) (with WSL2) and [VSCode](https://code.visualstudio.com/) with the "Dev Containers" extension. Open the HHK3template folder in VSCode. When VSCode asks to "Reopen in Container", accept it. You now get a ready terminal with the compiler at `/toolchain`.

### Linux

The same works with [Docker Desktop](https://docs.docker.com/desktop/setup/install/linux-install/), but the lightest path is podman with VSCode. Install podman and podman-compose (or use the docker-mirror from the podman-docker package). Then install the Dev Containers extension and set it to use podman. On Arch Linux this is what the maintainers use day to day.

You can also pull the image directly with `docker pull ghcr.io/classpaddev/hollyhock-3:v2.2.2`. With podman the same command works. Or you can build it yourself from the Dockerfile in the template repository.

### Recommended VSCode extensions

These come from the template's devcontainer config:

- `ms-vscode.makefile-tools`: Makefile support.
- `ms-vscode.cpptools` and `ms-vscode.cpptools-themes`: C and C++ support, plus color themes.
- `llvm-vs-code-extensions.vscode-clangd`: code intelligence. The template already sets it up with the right cross-compiler driver.
- `xaver.clang-format`: code formatting.
- `ZixuanWang.linkerscript`: linker script highlighting.
- `ms-azuretools.vscode-docker`: Docker integration.

### CI/CD

For automated builds, look at the GitHub Actions of the HHK3 template, which is a working example: [HHK3template actions](https://github.com/QBos07/HHK3template/actions). It builds the project on every push and pull request using the same toolchain image.
